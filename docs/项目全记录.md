# 山河游记 · 项目全记录

> **历史记录（Dify 早期版本）**：本文记录的是早期 Dify 架构与当时的计划，不能作为当前功能清单。当前 Web/CLI 主链使用 LangChain；请以[当前源码索引](源码索引.md)和[研发协作记录](05-研发协作/README.md)为准。

> AI 旅游攻略 Multi-Agent 系统 · 从设计到落地的完整历程

## 🎯 项目概述

输入任意中国目的地，AI 自动生成完整旅游攻略：路线地图、景点图鉴、美食、风土人情、天气预报、预算。

## 🏗️ 最终架构

```
用户输入 (前端 SPA)
    │
    ▼
FastAPI (/api/generate)
    │
    ▼
Python 编排器 (orchestrator.py)
    ├── Dify 意图解析器 ──→ 结构化意图 JSON
    ├── Dify 路线规划器 ──→ 多日行程 + 交通
    ├── Dify 内容生成器 ──→ 景点 + 美食 + 文化 (按城市并行)
    ├── 高德天气 API ──→ 天气预报 + 穿衣建议
    └── Obsidian 存档 ──→ 知识库积累
    │
    ▼
前端渲染 (Vanilla JS SPA)
    ├── 8 页面导航
    ├── 高德交互地图
    ├── CSS 进度动画
    └── 响应式布局
```

## 📋 技术栈

| 层 | 技术 | 作用 |
|----|------|------|
| Agent 编排 | Python asyncio | 串行+并行调度 3 个 Dify 工作流 |
| LLM 后端 | Dify 0.15.3 + DeepSeek | Prompt 管理、知识库、API 发布 |
| Web 后端 | FastAPI + Uvicorn | REST API、静态文件服务 |
| 前端 | Vanilla JS + CSS | SPA、地图、进度动画、零框架 |
| 地图 | 高德 JS API 2.0 | 安全密钥、编号标记、虚线路线 |
| 天气 | 高德天气 API (MD5签名) | 4天预报 + 穿衣建议 |
| 数据模型 | Pydantic v2 | 结构化数据校验 |
| 图片 | Playwright + 百度图片 | 自动抓取景点真实照片 |
| 知识库 | Obsidian + Markdown | 自动归档、双向链接 |
| 部署 | Docker (Dify) + Uvicorn | 虚拟机运行 |

## 🔥 核心难点 & 解决过程

### 难点 1：Gradio 的 innerHTML 陷阱

**现象**：高德地图永远显示"加载中"，JS 不执行。反复调试 Key、坐标、安全密钥全都没有用。

**根因**：Gradio `gr.HTML` 组件用浏览器 `innerHTML` 注入内容。HTML 规范规定 `innerHTML` 不执行 `<script>` 标签——不是 Gradio 的问题，是浏览器安全规范。

**解决**：弃用 Gradio 作为渲染层 → FastAPI + 独立 HTML/JS/CSS 前端。纯后端返回 JSON，前端 fetch 后渲染。

**教训**：任何需要 JS 交互的项目，不要用 Gradio 的 gr.HTML 做渲染。用 iframe 嵌入或独立前端。

### 难点 2：LLM JSON 输出不稳定

**现象**：Dify 返回的 JSON 被截断（`max_tokens` 不足）、尾部逗号、单引号、Markdown 代码块包裹。

**解决**：
- 按城市并行生成内容（每个城市 JSON 更小，不容易截断）
- 四级容错解析：直接解析 → 提取 Markdown 代码块 → 查找最外层 {} → 修复尾部逗号/单引号 → 补全截断 JSON
- Python 编排器补全 LLM 漏掉的默认值

**关键代码**：`tools/dify_client.py` 的 `_parse_json()` 和 `_fix_truncated_json()`

### 难点 3：高德地图安全密钥

**现象**：地图加载但坐标定位到北冰洋。

**根因**：高德 2.0 要求在加载 SDK 之前设置 `window._AMapSecurityConfig = { securityJsCode: "..." }`，顺序错了地图废了。

**解决**：安全密钥 `<script>` 必须放在 SDK `<script src="...">` 之前。

**关键文件**：`test_amap.html`（独立验证）、`frontend/index.html`

### 难点 4：前后端分离的曲折

项目经历了 3 次架构变化：

1. **纯 Gradio** — Python 字符串拼接 HTML，CSS/JS 混在 Python 里
2. **Gradio + 外部模板** — HTML 模板分离但 Gradio 渲染
3. **FastAPI + 独立前端** — 最终方案，真正前后端分离

### 难点 5：Dify 与 Python 的 Key 管理

3 个 Dify 工作流各有独立 API Key。最初设计了一个 `common_key` 回退机制，后来发现冗余——直接用 3 个独立 Key 更清晰。

**最终方案**：`config.py` 中 `intent_key` / `route_key` / `content_key` 各自独立。

### 难点 6：进度动画在 Gradio 中的限制

Gradio 的 `gr.Progress()` 只能显示文本进度条。迁移到 FastAPI 后，前端用 CSS 动画实现了 5 阶段旅行主题进度（浮动 emoji + 跳动圆点 + 阶段文案）。
