# 第19—21轮：DeepSeek联网补全独立复核

2026-10-23，用户授权“生成攻略依旧是deepseek，开始优化”。本轮保持已有DeepSeek生成流程，加入DeepSeek Search/Fetch补充景点票价、开放与预约线索及网页图片候选。

## 官方接口依据

- [DeepSeek网页搜索与抓取](https://api-docs.deepseek.com/zh-cn/guides/search/)：独立Search与Fetch JSON API，搜索可返回正文，Fetch返回Markdown；读取目标受站点可用性和访问策略影响。
- [Search返回结构](https://api-docs.deepseek.com/zh-cn/api/search/)：没有景点图片列表，`site_icon`是网站图标。
- [Fetch返回结构](https://api-docs.deepseek.com/zh-cn/api/fetch/)：只有标题和Markdown正文，不能假定必然含图片或完整动态售票信息。

本轮启动时，实际用户目录没有持久模型档案，仓库没有.env。未读取或打印真实凭据值。真实服务验收需要用户在界面中提供有效配置；离线替身不能证明厂商账号可用。

## 独立复验记录

**结论：第19—21轮本机离线实现通过，可进入真实DeepSeek账号试用。** 生成继续沿用DeepSeek主链，Search/Fetch是明确启用的独立工具。没有真实凭据，因此不能据此宣布实时票价、图片覆盖率或付费接口已验收。

### 已发现并修复

- 会话密钥在JSON持久化之前切换，失败后出现跨来源状态混用；持久密钥切换至会话密钥后无法彻底清除旧凭据。失败注入与清除行为已独立复验。
- 图片下载最初只预检DNS，后续连接可能再次解析；改为校验后固定公网IP、保留原Host与TLS SNI，禁用环境代理并逐跳验证重定向。修复过程中出现的未await HTTPX send问题也由独立下载用例检出并修复。
- 搜索只匹配城市导致同城其他景点资料误挂；Fetch标题正确而正文属于其他景点也可能被采纳。现在候选同时匹配城市及景点，正文重新确认目标，价格摘录受景点章节上下文约束；通用门票/开放时间子章节仍能提取实际内容。
- Python3.10总超时异常类别和取消后未取回gather异常的问题已修复；部分成功保留来源及实际调用计数。
- 新建模型档案后联网下拉未更新、缓存工具统计口径未区分原调用、安装模板环境变量默认值覆盖GUI开关，均已修复。模板新变量默认空白；显式环境覆盖会报告到UI，对应字段禁用并说明原因。

### 浏览器闭环

使用真实应用/编排/前端，模型、Search/Fetch、DNS和图片下载均用替身；配置、历史与图片位于独立临时目录，没有使用真实用户凭据或修改用户服务。

1. 从设置新建官方DeepSeek会话档案，同一对话框下拉立即可选，显式复用后启用联网。
2. 从输入生成攻略：1次Search、1次Fetch、1张图片安全下载并经Pillow校验；浏览器实际加载本地128×96测试图，明确标注内容与授权未核验。
3. 景点页保留来源链接、抓取时间、成人/儿童/套票起价原文。模型参考票价60与网页样例70/35/100起分开展示，网页票价标注不计入预算。
4. 实际下载JSON与Markdown并检查：含来源和票价线索，测试凭据字符串未进入导出。
5. 相同请求缓存命中；关闭联网后同一请求不会复用旧联网资料，景点页显示未发起Search/Fetch且恢复占位图。
6. 隔离服务重启后，从历史恢复原联网攻略，来源、票价原文和本地图片仍可用；最终缓存提示写明没有新增模型或Search/Fetch调用，工具计数标为原攻略统计。
7. 390px视口下景点页文档/内容宽度均375px；设置对话框362.4px，联网表单286px，无整页横向溢出。

证据目录为本会话visualizations目录，导出文件为`deepseek-web-guide-20261023.json`与`.md`，桌面和手机截图以`deepseek-web-`开头。截图中的绿块是刻意使用的离线测试图片，不是真实景区照片；票价也是带说明的测试数值。临时服务和标签页在验收后清理，未操作用户18001/8000服务。

## 真实使用边界

先启动实际应用，在模型设置中填写真实DeepSeek档案，再于“景点网页资料与图片线索”明确选择该官方档案并启用；代理模型凭据不会自动发送至官方工具域名。真实请求的账号权限、实时网页格式、景点覆盖率和图片使用许可尚未实测。缺失/错页/下载失败会保留状态和线索，不编造票价或图片；网页价格不自动进入预算。
