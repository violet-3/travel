## 第11轮

- 修复前：模块 docstring 内混入一条 `from datetime import ...`，实际 import 在第 11 行重复。
- 门票由固定日均改为按行程地点累加。复核确认三种输入都按预期：有标价按标价、无标价进待核实清单、无行程明细回退日均。
- 住宿城市系数改变了既有断言。**这是行为变更而非测试迁就**：西安两日游人均已知小计 ¥710 → ¥748。测试 `test_route_validation.py` 与 `smoke.py` 的固定数字同步更新，并在文档记录原因。
- 自查未覆盖：`_match_spot` 用"包含"匹配，可能把"故宫"匹配到"故宫博物院"（期望行为），也可能把"长城"匹配到"八达岭长城"（可接受）。未构造长名称互相包含的反例。

## 第12轮

- **发现并修复一个真 bug**：距离计算最初未过滤 `coordinate_verified`，模型自报坐标也参与了判断，违反第8轮"只有服务端富化层可写坐标可信性"的契约。修复后 `test_unverified_coordinates_are_ignored` 固定该行为。
- 自查确认：无坐标时 `checked=false`、不给地理扣分、note 明确写"无法判断"。
- 自查确认：`apply_feasibility` 限制 3 条并去重，重复调用不会追加重复警告。
- 未验证：Haversine 距离与实际道路里程的偏差比例；门槛（40/100/80/160 km）是经验值，未经真实出行数据校准。

## 第13轮

- 自查确认：城市后缀（"北京市" vs "北京"）能匹配到同一份预报；缺预报的日期单独标 `no_forecast`，不与其他日期共用一个结论。
- 自查确认：没有温度预报时衣物建议明确标注"可信度较低"，不假装精确。
- 自查确认：室内备选只给类别，未编造任何具体场馆名称。
- 未验证：高德天气字段在真实响应中的缺失形态（例如 `daypower` 为空字符串）下的表现，只按 `_as_int` 返回 None 处理。

## 第14轮

- 自查确认：六维度权重和为 1；分数固定在 0–100；问题清单去重。
- 自查中发现测试假设有误：最初构造的"完整攻略"仍会因待核价交通与门票待核实被扣分，说明评分规则确实反映了真实短板，不是测试写错。已改为构造真正完整的样本，并另建用例覆盖"不完整"的分支。
- 未验证：权重分配的合理性。当前比例是先验设定，没有用真实用户评价校准。

## 第15轮

- 自查确认：API Key 不参与 key 计算（测试 `test_api_key_is_not_part_of_the_key`）；改 Key 不会导致缓存失效，这是有意设计，因为结果与 Key 无关。
- 自查确认：损坏文件、版本号不符、过期条目都会返回 miss 并清理；写入失败返回 False 而不抛异常。
- 自查确认：缓存命中仍会写入一条新的历史记录，`history_id` 不重复。
- 自查确认：`force_refresh=true` 确实触发第二次模型调用（桩编排器计数为 2）。
- 未验证：多进程同时写同一缓存目录的行为。写入用临时文件 + `os.replace` 原子替换，但没有像图片索引那样加文件锁；并发场景下可能出现后写覆盖先写，不会产生损坏文件。
