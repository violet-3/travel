# 第十一至十五轮迭代 · 方案与实施记录

十轮迭代在离线范围内通过后，本轮继续从**攻略本身好不好用**出发找问题，而不是继续堆接口。以下五轮按"先修可信度、再补可用性、最后做自检与成本"的顺序推进。

## 起点：十轮之后仍然存在的五个问题

1. **门票是拍的，不是算的。** `_calculate_budget` 里写着 `tickets = 100 * days`，而 `Spot.ticket` 已经有数据却没被使用。行程里排了三个收费景点和排了一个免费公园，预算数字一模一样。
2. **住宿全国一个价。** 中等档 250 元/晚在北京和三线城市都按同一个数算，多城行程也不区分在哪过夜。
3. **没人管同一天跑得跑不完。** 上午故宫、下午外滩这种安排，编排器完全不报警；`pace` 字段只影响提示词，不影响任何校验。
4. **天气拿到了但没用起来。** 只输出一句穿衣建议，没有"这天下雨怎么办"，也没有打包清单。
5. **攻略生成完就结束了。** 用户不知道这份攻略哪里薄弱，只能自己逐页翻。

另外发现一处代码卫生问题：`agents/guide_generator.py` 顶部的模块 docstring 被一条 `from datetime import ...` 污染，实际 import 语句被包进了字符串里。

## 第11轮 · 预算可信度与代码卫生

| 项 | 内容 |
|---|---|
| 改动 | 修复 `guide_generator.py` 的 docstring；门票改为按行程实际安排的地点累加；住宿按过夜城市等级系数折算；新增费用结构占比与门票拆分字段 |
| 关键规则 | 景点有 `ticket > 0` 用标价；`ticket == 0` 或行程地点匹配不到推荐列表时按每处 ¥100 估算，并写入 `tickets_pending_spots`；每天至少按一处收费景点兜底，避免模型只写半天导致门票为 0；同一景点重复出现只计一次 |
| 住宿 | 基准价不变，乘城市系数（北京/上海 1.5、西安 1.15、安阳 0.8、未列出城市 1.0），按每晚实际所在城市分别计算 |
| 可解释性 | `tickets_known` / `tickets_estimated` 分开记录，`cost_share` 给出各项占比；交通占比超过 45% 时提示以铁路或航司报价为准 |
| 验收 | 新增 `tests/test_budget_estimate.py` 11 项；`tests/test_route_validation.py` 与 `tests/smoke.py` 中依赖旧固定单价的断言同步更新 |

预算数字因此发生变化：西安两日游人均已知小计由 ¥710 变为 ¥748（住宿 288 而非 250）。这是有意的行为变更，已在测试中固定。

## 第12轮 · 行程地理顺路与强度校验

新增 `tools/itinerary_feasibility.py`，只在**富化层已核验的坐标**上计算，模型自报坐标一律忽略。

| 检查 | 阈值 | 扣分 |
|---|---|---|
| 同日相邻两段通勤 | ≥ 40 km 提示核对是否同城，≥ 100 km 判为当天往返吃紧 | 10 / 18 |
| 单日移动总里程 | ≥ 80 km 提示预留交通时间，≥ 160 km 判为大量耗在路上 | 8 / 15 |
| 活动数 vs 节奏 | 轻松 2 个、不紧不慢 3 个、特种兵 4 个 | 8 |
| 粗估耗时 | 停留 2.5 小时/活动 + 距离按 40 km/h；轻松 9 小时、不紧不慢 11 小时、特种兵 13 小时 | 10 |

输出 `TravelGuide.feasibility`：总分、等级（A/B/C/D）、逐日明细、问题清单、位置覆盖率。没有可核验坐标时 `checked=false`，明确写"无法判断景点间通勤"，不因无法判断而扣分。

`apply_feasibility` 只把前 3 条问题写进 `route.warnings`，其余折叠为"另有 N 项"汇总，避免淹没预算与约束提示。

第一版实现有一个真 bug：距离计算没有过滤 `coordinate_verified`，导致未核验坐标也参与判断。测试把这个契约固定下来了。

## 第13轮 · 天气备选方案与行前清单

新增 `tools/prep_plan.py`，输出 `TravelGuide.prep`：

- **逐日应变**：按行程第 N 天对应日期匹配该城市预报。有降水给室内类别替代（博物馆、美术馆、图书馆、商场），较强降水追加景区开放确认提示；最高温 ≥ 35℃ 建议避开正午；最低温 ≤ -5℃ 提示结冰；风力 ≥ 6 级提示索道游船可能停运。匹配不到预报的日期显式标 `no_forecast`。
- **打包清单**：按温度区间给衣物，按天数给换洗量，叠加证件预订、随身电子、健康护理三组通用项；再从 `companion`、`constraints`、`preferences` 推导补充项（亲子、老人、少走路/无障碍、不爬山、摄影）。
- **边界**：室内备选只给类别不点名具体场馆；所有条目附 `basis` 说明依据；明确"预报时效有限，出发前 1 天再查"。

前端新增第 9 个页面"行前"，导航与渲染同步扩展；Markdown 增加"🎒 行前准备"段落。

## 第14轮 · 攻略质量自检

新增 `tools/guide_quality.py`，六个维度加权，全部确定性规则，不调用模型：

| 维度 | 权重 | 看什么 |
|---|---|---|
| 结构完整 | 20% | 标题、每日时段填充率、景点、文化内容 |
| 需求覆盖 | 20% | 目的地覆盖、天数一致、预算与日期是否填写、硬约束是否有说明 |
| 内容充实 | 20% | 景点数与天数比例、提示覆盖率、摄影机位、必吃清单、民俗内容 |
| 预算说明 | 15% | 待核价交通段、门票待核实项、是否填写预算、估算口径 |
| 位置与图片来源 | 15% | 坐标核验率、可用图片比例 |
| 行程可执行 | 10% | 复用第12轮评分，未检查时给 65 分并说明 |

输出 `TravelGuide.quality`：总分、等级、维度明细、去重后的问题清单。前端在概览页展示分数条与可折叠的问题列表，Markdown 增加"🔎 攻略自检"表格。

文档与代码都写明：**分数只衡量攻略自身完整度与边界说明，不代表事实经过核验。**

## 第15轮 · 生成缓存与文档收口

新增 `tools/guide_cache.py`：

- **缓存 key**：`sha256(规范化查询 + 规范化表单条件 + 档案 ID + 供应商/协议/模型/BaseURL/结构化方式)`，取前 40 位。API Key 不参与，测试固定了这一点。
- **TTL** 默认 30 分钟，最多保留 40 条，过期与超额在读写时清理。
- **只缓存成功结果**：失败、取消、没有 `route` 的对象都不写入；缓存命中不会被再次写回。
- **命中必须显式**：`TravelGuide.cache_hit` / `cache_age_seconds`，前端显示提示条与"强制重新生成"按钮，请求带 `force_refresh: true` 时绕过缓存。
- **新增接口**：`GET /api/cache` 返回条目数，`DELETE /api/cache` 清空。

### 真实链路试跑（本地样例）

用一份构造的"北京人文三日"数据把五轮改动串起来跑了一遍，确认链路连通，而不只是单元测试各自通过：

| 项 | 实际输出 |
|---|---|
| 门票 | ¥664 = 已标价 264（故宫 60 + 颐和园 30 + 天坛 34 + 古北水镇 140）+ 未标价 400（4 处 ×¥100，全部进待核实清单） |
| 住宿 | ¥1200 = 舒适档 400 × 北京系数 1.5 = 600/晚 × 2 晚 |
| 费用结构 | 交通 32% · 住宿 34% · 门票 19% · 餐饮 11% · 其他 4% |
| 可执行性 | 74 分 / C 级，抓出"第2天第1段通勤约 112 公里"；逐日里程 1.9 / 112.2 / 22.9 公里 |
| 行前 | 3 天逐日方案（Day2 "小雨转阴"触发室内替代）+ 5 组打包清单 |
| 自检 | 87 分 / A 级，六维度明细与 6 条可改进项（图片 0/7 是最大短板） |

试跑暴露并修复了两个问题：昼夜间天气相同时显示成"晴晴"，住宿说明只给基准价而未说明折算后的实际每晚价格。两处都已补测试。

可打开的产物：`output/preview-11-15.html`（9 个页面的真实渲染，HTML 由 `app.js` 原样产出并内联真实 `style.css`）与 `output/sample-guide.md`（Markdown 导出，含五个新章节）。

前端新增内容（第 9 页"行前"、可行性摘要、质量自检、缓存提示）通过 Node 沙箱加载 `app.js` 并直接调用 `rPrep` / `qualityBlock` / `rHome` / `rDays` 验证了渲染产物，同时固定了"`PAGES[1]` 仍必须是地图页"这一与 `switchPage` 耦合的假设。

## 验证边界

- 全部为离线验证：没有调用真实模型、高德 POI/天气或图片服务。缓存命中测试使用临时目录与桩编排器。
- 行程距离是直线距离，不等于实际道路里程；没有坐标时明确不给地理结论。
- 预算中的门票与住宿仍是规划估算，不是实时票价或房价。
- 质量分不是事实核验，"A"只说明这份攻略结构完整、边界说清楚。
- 前端改动只做了 JS 语法检查与服务端静态资源可访问性验证，未在真实浏览器中逐页点击 9 个页面，也未在 390px 视口下重新截图。
