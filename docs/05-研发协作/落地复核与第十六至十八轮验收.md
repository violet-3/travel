# 本机落地复核与第16—18轮验收

用户于 2026-10-23 授权继续检查优化空间，并根据实际情况分轮迭代。当前交付目标沿用已明确的本机个人旅行攻略工具；真实供应商接入必须由有效配置和真实请求验证，离线测试不能替代。

## 起点与独立复现

复核范围包括工作区尚未提交的第1—15轮代码，不重置既有改动。当前独立运行：179 项 Python 单元/集成测试、12 项 Node 测试、前端语法及 `git diff --check` 通过。配置与历史使用临时目录，未调用真实模型或高德服务。

另用隔离脚本复现了测试未阻止的实际问题：

| 场景 | 修复前结果 | 影响 |
|---|---|---|
| 一天仅有参考门票70元的活动 | 门票累计100元，多出30元且待核价列表为空 | 每日收费底价制造额外费用 |
| 两活动只有第一处有已核验坐标 | `checked=true`，但距离为空 | 没有任何有效通勤段也声称完成地理检查 |
| 景点和文化均为空 | 内容充实维度65分 | 缺失内容反而获得分数 |
| 只修改模型 temperature | 缓存键相同 | 配置变化仍复用旧攻略 |
| 缓存有非空 route，但 days 是非法字符串 | `ValidationError`，生成调用次数0 | 损坏缓存阻断生成，不能自愈 |

代码阅读同时发现：门票匹配不限定城市；行前清单声称“行程已避开登山”；CLI 直接把模型标题用作文件名；诊断请求没有明确关闭客户端。这些分别纳入以下轮次。

## 三轮验收约定

1. **第16轮：攻略可信度。** 删除门票强制每日收费；区分免费、未标价和模型参考价，保守匹配城市及名称；无有效通勤段不能给出已检查结论；不奖励空内容；行前清单不得保证未核验的约束或臆定气温。
2. **第17轮：缓存与故障恢复。** 损坏缓存自动回退；缓存读写失败不得丢失成功攻略；关键生成参数、相对日期及地图配置变化不误复用；诊断客户端在成功、异常及取消后释放。
3. **第18轮：本机交付。** 无外部请求的就绪检查；复用已有虚拟环境的 PowerShell 启动入口；不自动安装依赖或覆盖配置；CLI 文件名与输出目录边界；说明安装、启动、失败处理和真实接入验收步骤。

实现由已有实现工程师会话承担，复核官独立检查失败场景与当前代码。没有提交、合并、发布或公网部署授权。本次不新增账号、支付、预订或公共托管系统。

## 第16—18轮实施与最终回归

### 第16轮：门票、可执行性、行前与质量边界

- `Spot.ticket` 改为可空金额，并增加 `ticket_status`：`unknown`、`reference`、`free`。旧档案中的 `ticket=0` 仍解读为未知，正金额旧值解读为模型参考价；显式免费需标记 `free`。模型给出的门票始终注明未做官方核验。
- 预算只统计同城、景点名规范化后完全匹配的行程推荐景点。每个未知匹配点按每处¥100估算并列清单，免费点计¥0；不匹配的潜在收费活动不臆造金额，单独显示并把预算标为未完整核价。早餐、散步等只在活动名完整匹配通用模板时豁免，“拙政园散步”保留在待核价项。
- 行程可执行性只在至少存在一段两端都有已核验坐标时标记已检查；中间缺坐标时保留原始段序号，覆盖率按活动点位计数，不重复计共享端点。自检评分不再奖励空景点或空文化内容。
- 行前准备不声称已满足“不要爬山”等未核验条件；无温度数据时提供一般分层建议而不假设春季温度；充电宝提示用户核对出发机场与航空公司当前规定。

### 第17轮：缓存隔离与恢复

- 缓存读取同时校验完整 `TravelGuide` schema；损坏数据变为缓存未命中。读写缓存异常只记录固定异常类型，成功生成继续返回。
- 缓存身份包含模型生成参数、没有显式出行日期时的上海自然日，以及高德四类凭据的单向指纹。原始高德凭据不进入缓存文件或响应。网页保存/清除高德配置仍清理缓存；即使文件清理失败或环境变量改动后重启，新配置也会使用新的缓存身份。
- 模型诊断客户端在成功、异常和取消后执行屏蔽取消的异步关闭。普通与流式缓存命中也显式关闭为计算缓存身份而预建、但没有实际生成的 LangChain 客户端；命中用例确认未调用生成。
- 缓存攻略保留原始生成统计时，前端明确标为“原攻略生成统计”，缓存提示说明本次未产生模型调用。

### 第18轮：本机就绪与 CLI 交付

- `main.py --check` 做本地依赖导入、应用数据目录写入及配置是否存在检查，不连接模型或高德。依赖缺失时以标准库返回缺项、实际 `sys.executable` 和仓库 `requirements.txt` 的绝对路径修复命令，并以非零退出；缺少模型/地图配置只提示，不阻止 Web 启动。该状态表示本机可启动，不表示外部服务已连接。
- 新增 `start.ps1`：选择 `.venv` 或 `venv` 的 Python，先运行离线检查，通过后在当前 PowerShell 窗口启动 Web；不自动安装依赖，不覆盖 `.env`，无虚拟环境时打印操作命令。若执行策略拦截脚本，README 提供直接 Python 启动方式，不要求修改系统策略。
- CLI 使用持久化默认模型档案，支持 `--profile`；网页端“仅本次运行”档案无法跨进程传递，CLI 会给出说明。生成异常通过固定安全分类提示，不回显 Provider 原始异常。`--save` 文件名清理 Windows 禁用字符与设备名，并确认解析后路径留在 `output/`；清理后空标题返回可读错误和非零退出码。
- 首页、空状态和角色提示词已更新为九个内容维度。

### 最终回归结果

- 实现方本机：`venv\\Scripts\\python.exe -X utf8 -B -m unittest discover -s tests -p "test_*.py"`，213 项通过；`tests/smoke.py` 在临时图片目录、空地图配置和 HTTP 阻断桩下通过；Node 两个前端套件共 12 项通过；`node --check` 两个 JavaScript 文件通过；`start.ps1` PowerShell 语法解析与 `git diff --check` 通过。`main.py --check` 在临时数据目录报告本机可启动，同时明确未连接模型或地图服务。
- 决策复核官最终独立报告：最新代码全量 Python 213 项、Node 12 项、隔离 smoke、两份 JavaScript 语法检查和 diff 检查通过；另写18项仓库外独立行为用例并全部通过，未计入上面213项。包括上海跨零点、高德配置变化不经clear即改变缓存身份，以及使用真实编排器和替身客户端证明普通/流式缓存命中不执行模型生成且客户端关闭。真实浏览器检查九页桌面与390px布局、缓存提示、强制刷新完整生成、取消后旧稿保留和Markdown下载内容。图片缓存两份既有文件的SHA256未变化。浏览器使用模型替身和临时数据，不代表真实模型/高德服务验证。
- 决策复核官独立验证 PowerShell 桩行为：预检通过才启动 app，预检失败以 1 退出且不启动。实现方仅做了脚本语法解析；没有调用付费模型或高德服务，也没有安装/升级依赖。

复核官还实际创建了不安装依赖的空虚拟环境：`main.py --check` 无 traceback，列出缺项、绑定该虚拟环境解释器与仓库 requirements 绝对路径的修复命令，退出1；在项目虚拟环境及临时数据目录中则报告本机可启动，并明确模型/地图未配置以及未执行连接验证。
